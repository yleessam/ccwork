# 검색 기능 정의서 (확정)

> 원본: spec-original.md | 확정일: 2026-06-04

---

## 기능 개요

노트 목록에서 제목과 내용을 기준으로 노트를 검색할 수 있다.
검색은 이미 로드된 `notes[]`를 클라이언트에서 필터링하는 방식으로 동작한다.

---

## Primary User

노트를 여러 개 쌓은 사용자 본인. 협업·공유 시나리오 없음.

---

## 최소 동작 시나리오

1. 검색창에 키워드를 입력하면 제목·내용에 해당 키워드가 포함된 노트만 목록에 표시된다
2. 검색어를 모두 지우면 전체 노트 목록으로 돌아온다
3. 어떤 노트에도 매칭되지 않으면 "검색 결과가 없습니다" 메시지가 표시된다

---

## UI 패턴

### 배치

사이드바 상단 — "새 노트" 버튼 아래, `NoteList` 위에 `SearchBar` 컴포넌트를 삽입한다.

```
[ 새 노트 버튼         ]
[ 🔍 검색어 입력...    ]  ← SearchBar
─────────────────────
  NoteItem
  NoteItem
  ...
```

### SearchBar 스타일

- pill 형태 컨테이너 + 왼쪽 검색 아이콘
- 입력창은 `NoteEditor` 제목 입력 패턴 재사용 (`bg-transparent border-none outline-none`)

---

## 상태 관리

- 검색어(`query`)는 컴포넌트 로컬 상태로 관리
- `NotesContext`에 추가하지 않음 — 순수 UI 상태이므로 전역 불필요
- 필터링은 렌더 시점에 파생: `filteredNotes = filterNotes(notes, query)`

---

## 필터 로직

- 순수 함수 `filterNotes(notes: Note[], query: string): Note[]`로 분리
- 제목(`title`) + 내용(`content`) 모두 검색 대상
- 대소문자 구분 없이 비교 (`toLowerCase()`)
- 태그 검색 확장 시 이 함수에 조건만 추가

---

## 경계 조건

| 상황 | 처리 |
|------|------|
| 빈 문자열 입력 | 전체 목록 표시 |
| 공백만 입력 | trim 후 빈 문자열 → 전체 목록 표시 |
| 매칭 노트 없음 | "검색 결과가 없습니다" 메시지 표시 |
| 검색어 최대 길이 | 제한 없음 |
| 검색 중 노트 추가/삭제 | `notes[]` 변경 시 필터 결과 자동 갱신 (파생 상태) |

---

## 에러 처리

검색 전용 에러 처리 없음. 기존 `loading → error → empty → 정상` 가드 클로즈 패턴 유지.

---

## 성능

debounce 없이 입력 즉시 필터링. `Array.filter()`는 현재 노트 규모에서 무시할 수 있는 비용.

---

## 용어 정의

| 용어 | 정의 |
|------|------|
| 검색어 (query) | 사용자가 SearchBar에 입력하는 텍스트 |
| 필터링 (filtering) | query로 `notes[]`를 줄이는 클라이언트 동작 |
| 검색 결과 (filteredNotes) | 필터링된 노트 배열. query가 비어있으면 전체 notes와 동일 |
| SearchBar | 검색 입력 UI 컴포넌트 |
| filterNotes | 필터 로직을 담은 순수 함수 |
